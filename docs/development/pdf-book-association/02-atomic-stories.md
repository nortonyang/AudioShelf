# 原子任务与原子用户故事

## AT-201：规范化同名匹配

用户故事 US-201：作为用户，我希望 `三体.pdf` 能对应书名“ 三体 ”或目录“三体”，以便不必手工逐本设置。

验收标准：Given 大小写、宽度、空格或标点差异，When 规范化，Then 同名结果相等；Given 不同文字，Then 不匹配。

## AT-202：持久化 PDF 授权

用户故事 US-202：作为用户，我希望 PDF 关联在应用重启后仍存在，以便持续使用。

验收标准：Given PDF 文件名和 bookmark，When JSON 往返，Then两字段保持；旧 JSON 缺少字段仍可解码。

## AT-203：打开 PDF

用户故事 US-203：作为用户，我希望点击按钮用默认阅读器打开 PDF，以便边听边看。

验收标准：Given 有效 bookmark，When 点击打开，Then 系统默认 PDF 应用接收文件；Given 文件移动，Then显示明确错误且不丢失书籍。

## AT-301：文件夹导入自动关联

用户故事 US-301：作为用户，我希望导入含同名 PDF 的有声书文件夹时自动完成关联，以便零额外操作。

验收标准：Given `三体/` 内含 MP3 和 `三体.pdf`，When 导入文件夹，Then 新书立即显示 PDF 入口。

## AT-302：批量关联已有资料库

用户故事 US-302：作为用户，我希望一次选择多个 PDF 并按文件名匹配现有书籍，以便快速整理资料库。

验收标准：Given 多个 PDF 与多本书，When 选择文件，Then 唯一同名候选被关联，并反馈已匹配及未匹配数量；歧义候选不自动关联。

## AT-303：详情入口

用户故事 US-303：作为用户，我希望在书籍详情看到 PDF 文件名和“打开 PDF”，以便确认对应关系。

完成定义：无 PDF 时不显示按钮，有 PDF 时按钮可访问且错误可理解。

## AT-401：验证与交付

用户故事 US-401：作为维护者，我希望匹配规则、持久化和应用构建都有证据，以便安全接手。

完成定义：CoreChecks、StoreChecks、build、codesign 和启动检查通过。
