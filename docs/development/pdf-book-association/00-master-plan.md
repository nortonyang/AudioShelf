# 总开发阶段文档：PDF 书本自动关联

## 目标

让 AudioShelf 根据文件名将本地 PDF 与有声书对应：导入文件夹时自动发现同名 PDF；已有资料库可批量选择 PDF 自动匹配；关联后从图书详情用系统默认阅读器打开，并在重启后保持访问授权。

## 非目标

- 不解析 PDF 内容、目录、封面或文字。
- 不内置 PDF 阅读器，不复制或修改用户 PDF。
- 不做模糊语义匹配；首版只做可解释的规范化同名匹配。

## 当前证据

- `Audiobook` 已由 Codable JSON 持久化，可向 schemaVersion 1 增加可选字段而兼容旧快照。
- 现有 `BookmarkService` 已处理 security-scoped bookmark 生命周期。
- 文件夹导入已持有目录访问范围；单独 MP3 授权不能可靠扫描旁边的 PDF，因此已有资料库需要显式选择 PDF。
- 详情页已有播放与章节重新定位入口。

## 假设

- PDF 基础文件名通常等于书名、导入文件夹名或音频所在目录名。
- 匹配忽略大小写、全半角、重音、空格和标点，但保留字母、数字与汉字。
- 同一 PDF 若匹配多本同名书则不自动选择，避免错误关联。

## 风险

| 风险 | 影响 | 缓解方案 | 负责人 |
| --- | --- | --- | --- |
| 规范化后同名冲突 | PDF 关联错误 | 多个候选时标记未关联，由用户调整文件名 | Codex |
| 沙盒无法访问旁路 PDF | 自动扫描失败 | 文件夹导入自动匹配；已有书通过文件选择器授权 | Codex |
| bookmark 陈旧 | 重启后打不开 | 打开时刷新陈旧书签并保存 | Codex |
| JSON 旧数据缺少 PDF 字段 | 解码失败 | 新字段使用 Optional，保持 schemaVersion 1 兼容 | Codex |

## 验证策略

- CoreChecks 覆盖中英文、标点、大小写和非同名案例。
- StoreChecks 覆盖 PDF bookmark 和文件名 JSON 往返。
- release 构建、签名、应用启动必须通过。
- 人工验收：同目录同名 PDF 自动出现；批量关联后可从详情打开。
