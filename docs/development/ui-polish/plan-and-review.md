# AudioShelf 页面优化：规划与审核

## 目标

在不改变导入、匹配、播放和持久化行为的前提下，优化资料库卡片、侧边栏、图书详情头部和章节列表，使信息层级更清楚、长文本更稳定、选中与播放状态更容易辨认。

## 当前证据

- 当前窗口实测尺寸约为 `1070 × 762`，三栏结构正常。
- 资料库卡片主要依赖整块蓝色背景表达选中状态，书名、长作者和章节信息层级较弱。
- 详情头部中长标题、长作者、来源和操作按钮纵向堆叠，播放按钮与主要信息距离较远。
- 多章节长列表中，普通章节与当前章节主要依赖一个小图标区分，行点击区域和视觉分组偏弱。
- 侧边栏只有栏目名称，缺少资料库、最近播放和历史数量反馈。

## 范围与非目标

- 优化 `BookGridView` 卡片边界、选中/悬停状态、metadata 和进度显示。
- 优化 `BookDetailView` 头部排版、metadata 分组、主要操作与章节标题栏。
- 优化章节行的编号、点击区域和当前播放高亮。
- 给侧边栏增加对应数量，并设置合理的最小窗口尺寸，避免极窄窗口破坏三栏布局。
- 不改动数据模型、导入服务、PDF 匹配、播放行为或用户资料库内容。
- 本轮不引入自定义主题、第三方 UI 库或新的设置页面。

## 风险与缓解

| 风险 | 影响 | 缓解方案 |
| --- | --- | --- |
| 长作者或章节标题挤压操作区 | 截断、按钮换行 | 主要信息设置明确 line limit，动作使用独立水平组。 |
| 章节行增高导致首屏显示减少 | 扫描效率下降 | 只增加少量垂直 padding，标题保持单行优先。 |
| 视觉改动误伤交互 | 播放、右键或双击失效 | 保留现有手势、context menu 和调用路径，使用实际 UI 复核。 |
